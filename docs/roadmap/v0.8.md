## 2) 4대 줄기 + Wave / 우선순위

> 줄기별 한 줄 정의와 북극성 연결. Wave = 착수 순서(W1 = 즉시·기반, W2 = 핵심 가치, W3 = 확장·마감). P0=차단 해소 / P1=이번 마일스톤 필수 / P2=권장 / P3=보류 가능.

| 줄기 | 정의 | 북극성 | 핵심 Wave |
|---|---|---|---|
| **A. 데이터 규모** | 곡 수집 확대 + 음역대 자체 분석 backfill 로 추천 풀을 키운다 | **북극성** — 추천 품질은 매칭 가능한 곡 수에 비례 | W1 backfill(미보유 271 해소) → W2 대량 import(#1705) |
| **B. UX 품질** | 전 페이지 점검(#1708/#1709) 후속 개선 + `/recommend` 개편(#1727) 으로 프로덕션 완성도 | P-A~G 전부의 노출 표면 | W1 `/recommend` 개편 → W2 전 페이지 폴리시 → W3 마감 |
| **C. 페르소나 완성** | P-A~G 충족도 점검 + P-D·P-E be 검증·구현 + P-F·P-G 선행 | P-A~G 직격 | W1 P-D/P-E be(#1598/#1599) → W2 P-D fe(#1601) → W3 P-F/P-G 선행 spec→구현 |
| **D. 신뢰성·운영** | 디스크 cron + rev-gate 정상화 + hung 가드로 자율 사이클 안정화 | 자율 운행 기반(모든 줄기 enabler) | W1 디스크 #1653 + rev-gate #1649 → W2 hung 가드 |

**Wave 횡단 순서 원칙**
- **W1 = D(신뢰성) 우선** — 디스크 95%·rev-gate 오fail 은 다른 모든 줄기의 PR 머지를 막는 차단 요인. 깨진 기반 위에 쌓지 않는다(`overnight-2026-06-02.md` 운행 원칙 계승).
- **A(데이터) 와 C(페르소나) 는 결합** — 음역대 미보유 곡(271)이 추천 풀에 들어와야 P-A/P-E/P-F 매칭이 의미를 가진다. backfill(A) 이 페르소나 be(C) 의 데이터 enabler.
- **B(UX) 는 병렬 가능** — fe 사이클 독립 트랙. 단 `/recommend` 개편(#1727)은 P-D 사회자 입구 강등을 포함하므로 C 와 정보 정합 필요.

## 4) 중단 조건 · 릴리즈 정책

### 중단 조건 (이 줄에서 멈추고 사용자 확인)
- **법무 게이트 미통과** — A 줄기 외부 수집·import 확대 시 `legal-risk-data-collection-and-pii.md` High 등급 미해소면 착수 중단.
- **데이터 파괴·시크릿·외부 발신** — 곡 데이터 대량 삭제/덮어쓰기, 운영 DB 덤프 공유, 외부 API 키 노출 위험은 자율 진행 금지(CLAUDE.md §4 보안).
- **차단(D 줄기 미해소)** — 디스크 95%·rev-gate 오fail 가 살아 있으면 다른 줄기 PR 머지 신뢰 불가 → D 우선 해소 후 재개.
- **페르소나 신규 데이터 의존** — P-F/P-G 가 곡 신규 속성(킬링파트·듀엣)을 요구하므로, 데이터 설계 spec 합의 전 구현 착수 중단.

### 릴리즈 정책
- **평소 사용자 확인** — develop → main release 는 high-stakes 로 분류, **사용자 명시 확인 후** 진행(CLAUDE.md §4 자율 default 예외 + [[feedback-rev-release-gate]]). 자율 사이클은 develop 까지만 머지.
- 릴리즈 형식: `release: vX.Y.Z` 제목, `type` 별 changelog 그룹핑, **Merge commit**(Squash 금지), 머지 후 태그 + `gh release create`(CLAUDE.md §8).
- 릴리즈 게이트: rev 사이클 통과 PR 만 포함, CI green, dev 배포 E2E 검증.
