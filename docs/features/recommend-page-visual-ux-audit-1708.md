# /recommend 페이지 스크린샷 기반 시각 UX 점검 + 개선안

> 사용자 directive(이슈 #1708): "/recommend UX 가 사용성 부족 + 혼란스럽다. 스크린샷 찍어
> 경험을 분석하라." 본 문서는 **dev 라이브 화면을 실제로 렌더해 캡처한 시각 증거** 기반 점검이다.
> 코드 라인 단위의 전수 점검은 [[recommend-flow-ux-audit]](2026-06-03)가 SoT — 본 문서는 **그것이
> 잡아내기 어려운 "실제로 보면 드러나는" 시각·경험 갭**에 집중하고, 겹치는 항목은 시각 증거로
> 보강만 한다(중복 신설 금지). 구현은 fe 사이클 후속 PR 단위 — 본 문서는 점검 + 우선순위 개선안까지.

## 1) 점검 방법 (증거)

- 진입 경로: `/voice-range`(직접 선택, 기본 C3~A4) → "추천 받기" → `/recommend` (실 BE 응답).
- 캡처 매트릭스: **뷰포트 2** (모바일 375px / 데스크톱 1280px) × **상태 4** (초기 / 의도 모드 ON /
  분위기 필터 ON / 사회자 모드) = **8컷**. `docs/features/assets/recommend-ux-1708/` 에 커밋.

## 2) 점검 결과 — 시각·경험 갭

### A. 정보 위계 / 시선 흐름

**A-1. "결과" 페이지인데 결과가 fold 한참 아래 — 선택 UI가 화면을 점령 (🔴 신규)**
- 모바일 초기 진입(`mobile-recommend-initial.png`): 첫 곡 카드가 보이기까지 사용자가
  **헤더(음역대 + 음역 직관 막대) → "다 같이 즐길 곡" 카드 → 의도 모드 토글 → 분위기 칩 6종 →
  나이대 칩 6종**, 즉 4개 선택 블록을 지나야 한다. 제목은 "추천 결과"인데 정작 결과는 첫 화면 밖.
- 4개 블록이 모두 부제 "(선택)"임에도 시각 비중은 결과 못지않게 크다 → "이걸 다 채워야 추천이
  나오나?" 하는 입력 압박을 준다(실제로는 음역대만으로 이미 결과가 채워져 있음).
- 개선 방향: 결과를 먼저 보여주고 필터/모드는 (a) 접이식(accordion/"필터" 버튼) 또는 (b) 결과
  상단의 얇은 1줄 컨트롤 바로 축소. 첫 진입에서 "추천이 이미 나왔다"가 즉시 보이게.

**A-2. 유사 스타일 모드 컨트롤 3종이 위계 없이 나열 (🔴 신규)**
- 한 화면에 시각적으로 비슷한 pill/카드형 컨트롤이 셋 — 상호관계가 불명확:
  1. **"다 같이 즐길 곡 추천받기"** (neutral 카드) → 실제로는 `/recommend/host` **페이지 이동 링크**
  2. **"안 망할 곡 추천받기"** (의도 모드 토글, 켜면 brand 색) → **현재 페이지 내 토글**
  3. **"리스트 / 스와이프"** (세그먼트 토글) → **뷰 전환**
- 셋 다 둥근 표면 + 굵은 라벨이라 "무엇이 다른 화면으로 가고, 무엇이 그 자리에서 바뀌는지"가
  시각만으로 구분되지 않는다. 1번이 토글처럼 보여 잘못 누르면 다른 화면으로 튄다.
- 개선 방향: 이동(navigation)·토글(filter)·뷰(view) 세 역할을 시각 언어로 분리 — 예: 1번은 화살표/
  ">" 어포던스를 가진 링크 행으로, 2번·필터는 한 "추천 다듬기" 그룹으로 묶고, 뷰 토글은 결과 헤더에.

**A-3. 음역 직관 막대가 헤더에서 가장 무거운 요소 (🟡 신규)**
- 헤더의 `VoiceRangeIntuition` 막대가 거의 풀폭 짙은 바로 렌더돼(`*-recommend-initial.png` 상단)
  시선이 제일 먼저 꽂히지만, 담는 정보(C3~A4 + "평균보다 높음")는 보조적이다. 시각 비중 ↔ 정보
  중요도가 역전. 톤다운(높이/대비 축소) 또는 결과 영향이 없으면 접이식으로.

### B. 혼란 지점 / 라벨

**B-1. "다 같이 즐길 곡" 의도 불명 (🔴 — directive 명시 + 시각 보강)**
- directive가 직접 지목한 항목. 결과 위 prominent 카드로 떠 있어 일반(혼자 부를) 사용자에게
  "내가 받을 추천이 이건가?"라는 오인을 준다. 실제로는 **모임 사회자용 별도 시퀀스 화면**으로 가는
  입구다. 부제("모임 사회자용 — 도입·고조·마무리")가 있으나 카드 위치·비중이 너무 1차적.
- 사회자 화면 진입 후(`*-recommend-host.png`)도 "도입 4 / 고조 3 / 마무리 3" 탭과 "다음(고조)으로"
  버튼의 흐름이 첫 노출에 학습 부담이 크다. 진입 입구를 결과 흐름과 분리(2차 액션으로 강등)하는
  것이 우선.

**B-2. 세 그룹 모두 "(선택)" — 필수/배타/누적 관계 불명 (🟡 신규)**
- "의도 모드", "분위기", "나이대" 가 모두 "(선택)" 부제만 달고 나열돼, 서로 배타인지 함께 누적되는지,
  비워도 되는지가 화면에서 읽히지 않는다. 한 줄 안내("아무것도 안 골라도 음역대만으로 추천됩니다")
  또는 그룹 묶음 헤더로 의도를 명시할 여지.

**B-3. 카드 우상단 3지표(난이도·키·음역%) 의미 비노출 (🟡 신규, 표면 한정)**
- 카드 표면(`*-recommend-initial.png` 카드)에 "Easy/Hard" 배지 + "키 A Minor" + "음역 97%"가
  나란히 뜨지만 라벨만으론 관계·의미가 모호하다. 특히 "키 A Minor"는 비음악인에게 전달력이 약하고,
  "음역 97%"가 곡의 음역인지 내 음역 적합도인지 표면만으론 구분 어렵다(상세 모달엔 설명 있음).
- 표면 정보 자체는 절제돼 있으므로(모달로 위임 — `SongCard.tsx` 모달 모드) **경미**. "음역 97%"를
  "내 음역 적합 97%"처럼 의미를 담은 라벨로 다듬는 정도 권장.

### C. 사용성 / 반응형

**C-1. 데스크톱 단일 컬럼 — 거대 좌우 여백 (🟡 — 기존 E-1 시각 보강)**
- `desktop-recommend-initial.png`: 1280px 화면에서 `max-w-2xl` 단일 컬럼이 가운데만 채우고 양옆이
  광활하게 비어 "모바일 화면을 확대한 듯" 보인다. 정보 밀도 낭비. [[recommend-flow-ux-audit]] E-1
  과 동일 결론(모바일 우선이라 P3) — 본 점검은 **시각 증거 추가**만, 항목 신설 아님.

**C-2. 하단 고정 탭바와 콘텐츠 겹침 가능 + 기능 중복 (🟡 신규)**
- fullPage 캡처(`*-recommend-host.png` 등)에서 하단 고정 탭바(홈/측정/추천/이력/북마크)가 카드 위에
  겹쳐 찍힌다. 스크롤 끝에서 마지막 카드·CTA("음역대 다시 입력" / "다음으로")가 탭바에 가려질 수
  있으니 피드 컨테이너 `padding-bottom`(safe-area 포함) 확인 필요.
- 또한 탭바 "측정" ↔ 헤더 "음역대 다시 입력" 링크가 기능 중복 — 헤더 보조 링크 정리 여지.

**C-3. 필터/모드 적용 피드백이 결과 교체뿐 (🟡 — 기존 F-1 보강)**
- 분위기 ON(`*-recommend-filter-on.png`) 시 칩만 brand 색으로 바뀌고 결과가 재발화되나, "지금 N개
  조건이 적용됨 / 초기화" 같은 상태 요약이 없다. 여러 블록을 거친 뒤 "내가 뭘 켜놨는지" 추적이
  어렵다. [[recommend-flow-ux-audit]] F-1 과 동일 — 활성 개수 표시 + 초기화 1버튼 권장.
