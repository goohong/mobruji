# 외부 데이터 수집·사용자 PII 처리 법적 리스크 레지스터

> ⚠️ **본 문서는 변호사 자문을 대체하지 않는다.** 범위는 "리스크 식별 + 문서화" 수준이며,
> 서비스 정식 출시(production) 전 또는 외부 수집 경로 신설 시 전문 법무 자문이 별도로 필요하다.
> 본 문서는 흩어져 있던 법적 리스크를 단일 레지스터로 모으고, 각 리스크의 등급·완화 방안·
> 미해결 오픈 이슈를 박제해 후속 ADR/구현 PR 의 진입점을 명확히 하는 것이 목적이다.

## 1) 개요 (What / Why)
- mobruji 는 (a) 곡 카탈로그·메타데이터·앨범 커버를 **외부 출처에서 수집**하고, (b) 사용자의
  **음역대·선호(기호) 등 개인 데이터를 측정·저장**한다. 두 축 모두 저작권·약관(ToS)·개인정보
  관점에서 법적 리스크를 동반한다.
- 기존에 ADR-0006(YouTube audio ToS)·ADR-0013(익명 sessionId TTL/PIPA)·ADR-0029(앨범 커버
  라이선스)·`song-metadata-source.md`·`04-security-policy.md` 등에 리스크가 **흩어져** 있어,
  전체 노출 표면을 한눈에 보거나 미해결 항목을 추적하기 어려웠다.
- 본 spec 은 그 리스크들을 (1) 음원/가사 저작권, (2) 외부 사이트/플랫폼 약관 수집 허용 여부,
  (3) 사용자 음역대·기호 등 개인정보 처리·보관 — **세 축**으로 통합 정리한다.
- 대상 액터: 의사결정자(서비스 출시 go/no-go), be/fe/plan sub-agent(수집·저장 코드 구현 시
  본 레지스터를 사전 점검), rev 사이클(보호 영역/외부 연동 PR 의 추가 신중도 가중).

## 2) 사용자 시나리오
직접 사용자가 보는 화면은 없다. 다음은 거버넌스·운영 시나리오다.

1. **외부 수집 경로 신설 검토** — be/plan 이 새 외부 출처(예: 신규 가사 API, 신규 크롤링 대상)를
   추가하려 할 때, 본 레지스터에서 해당 축의 리스크 등급·완화 조건을 먼저 확인한다.
2. **PII 필드 추가 검토** — 사용자에게서 새 개인 데이터(예: 생년·연락처)를 수집하려 할 때, §5-3
   의 PII 처리 룰과 ADR-0013 라이프사이클을 점검한다.
3. **출시 전 법무 게이트** — 서비스 정식 출시 전, 본 레지스터의 "상(High)" 등급 미해결 항목이
   전문 자문으로 해소됐는지를 go/no-go 체크리스트로 사용한다.
4. **rev 신중도 가중** — 외부 연동/보호 영역 변경 PR 에서 rev 가 본 레지스터를 가중 정보로 참조.

## 3) 요구사항
### 기능 요구사항(문서 산출물)
- [x] 세 축(저작권 / 약관 / PII) 각각에 대한 리스크 항목·등급·완화 방안·오픈 이슈 정리.
- [x] 리스크 등급 척도 정의(상/중/하 = 발생가능성 × 영향).
- [x] 기존 ADR/spec 으로 이미 결정·완화된 항목을 교차 참조(중복 결정 금지).
- [x] 미해결(법무 자문 필요/후속 ADR 필요) 항목을 §8 오픈 질문 + §6 후속 트랙으로 분리.

### 비기능 요구사항
- 본 문서는 **결정을 새로 내리지 않는다**(이미 ADR 로 결정된 것은 인용만). 신규 결정이 필요하면
  별도 ADR 로 분리한다(예: 크롤링 전면 금지 정책의 형식화는 후속 ADR 후보 — §8 Q3).
- 코드 변경 없음. 본 spec 머지가 어떤 수집/저장 동작도 바꾸지 않는다.
- `06-domain-model.md §7`(오픈 이슈)은 canonical — 본 spec 은 §7 을 편집하지 않고 **참조만** 한다
  (D2 "곡 메타데이터 출처 — 법적 리스크 검토 필요"가 본 spec 의 §5-1/§5-2 와 연결).

## 4) 범위 / 비범위 (중요)
### 포함
- 외부 데이터 수집 3축(음원/가사 저작권, 외부 플랫폼 ToS, PII)의 리스크 식별·등급·완화 정리.
- 기존 결정(ADR-0006/0011/0013/0029, `song-metadata-source.md`)의 교차 참조 인덱스.
- 출시 전 법무 게이트에서 점검할 미해결 항목 목록.

### 제외 (Out of Scope)
- **전문 법무 자문 자체** — 본 문서는 자문을 대체하지 않는다. 출시 전 별도 진행.
- **신규 결정** — 크롤링 금지 정책 형식화, 개인정보 처리방침(Privacy Policy) 문구 확정 등은
  본 spec 이 결정하지 않고 후속 ADR/별도 산출물로 분리(§8).
- **개인정보 처리방침 / 이용약관 법무 문서 작성** — 출시 단계 별도 산출물. 본 spec 은 그 문서가
  다뤄야 할 리스크 항목만 식별.
- **해외 규제 전수 검토** — 1차는 한국(PIPA) + 외부 출처 약관 중심. GDPR/CCPA 등은 해외 출시
  시점에 별도 검토(§5-3 에 GDPR 정합성 일부만 ADR-0013 인용으로 언급).

## 5) 설계 — 리스크 레지스터

### 등급 척도
| 등급 | 의미 | 기준 |
|---|---|---|
| **상 (High)** | 출시 차단 가능성 / 권리자·플랫폼의 직접 조치(소송·차단) 리스크 | 발생 시 서비스 중단·법적 책임 직결 |
| **중 (Medium)** | 약관 위반·정책 위반 소지 / 조건부 허용 | 완화책 미비 시 차단·경고 가능, 조건 충족 시 해소 |
| **하 (Low)** | 합법 경로 확보됨 / 잔여 운영 리스크만 | 기존 결정으로 1차 완화됨, 모니터링 수준 |

### 5-1) 축 (1) — 음원/가사 저작권

| ID | 리스크 항목 | 등급 | 현 상태(완화 근거) |
|---|---|---|---|
| C1 | **음원(audio) 복제·보관** — 분석을 위해 원곡 audio 를 시스템에 임시라도 보관 시 복제권 침해 소지 | **상** | ADR-0006 가 PoC 한정 YouTube extract 채택 + "출시 전 법무 자문·ADR 갱신" 명시. **운영 단계 미해소** |
| C2 | **가사(lyrics) 수집·표시·저장** — 가사는 어문저작물로 별도 저작권. 현재 수집/표시 안 함 | **중** | 현 제품은 가사 미사용. 향후 가사 표시 기능 도입 시 신규 리스크 — **사전 자문 필요** |
| C3 | **앨범 커버 아트 표시** — 커버 이미지의 저작권/약관 | **하** | ADR-0029: iTunes Search URL 직접 링크 + **이미지 바이트 미저장**(URL 문자열만 캐싱), CAA(CC0/CC) 폴백 — 약관 준수 설계 |
| C4 | **곡 메타데이터(제목/아티스트/키/BPM 등) 사실 정보** — 사실 데이터는 저작권 약함, 단 DB 권리(편집저작물) 주의 | **하** | `song-metadata-source.md`: 수기 시드 + MusicBrainz(CC0) 보강. 크롤링 비채택 |

**완화 방안**
- **C1(상)**: ADR-0006 의 "PoC 한정" 경계를 유지. 분석 후 audio 즉시 삭제 + 캐시/로그 보관 정책
  엄격화(분석 산출물인 음역/키/BPM 수치만 보존, audio 바이트 비보존). 운영 진입 전 ADR-0006
  재평가 + 법무 자문(라이선스 협의 또는 합법 데이터셋 대체)이 **출시 차단 게이트**.
- **C2(중)**: 가사 기능은 현재 비범위. 도입 시 가사 제공 라이선스(예: Musixmatch 등 공식 API)
  확보 전 표시 금지. 사용자 입력 가사도 UGC 책임 분배 검토.
- **C3(하)**: ADR-0029 룰 유지 — 이미지 재호스팅 금지, `coverArtFetchedAt` 주기 재검증, 출처
  표기 약관 준수.
- **C4(하)**: 사실 메타데이터만 보관. 외부 DB 의 편집저작물성 권리를 침해하지 않도록 대량 복제
  대신 식별자(ISRC/MBID) + 자체 큐레이션 우선.

**오픈 이슈(이 축)**: C1 운영 단계 audio 출처 미해소(→ §8 Q1, ADR-0006 재평가 의존),
C2 가사 기능 도입 시 라이선스 경로 미정.

### 5-2) 축 (2) — 외부 사이트/플랫폼 약관(ToS) 수집 허용 여부

| ID | 외부 출처 | 등급 | 약관/수집 상태 |
|---|---|---|---|
| T1 | **YouTube** (yt-dlp audio extract) | **상** | YouTube ToS 는 download 를 일반 제한 → yt-dlp 사용은 약관 위반 해석 가능. ADR-0006: **PoC 한정** |
| T2 | **TJ/금영 노래방 사이트 크롤링** | **상** | `song-metadata-source.md §5-3`: 약관·저작권 리스크 큼 + AGPL 프로젝트에서 **권장 비추천** → 수기 입력 채택(비채택) |
| T3 | **Spotify Web API** | **중** | 공식 API 지만 약관상 **데이터 캐싱 제약**(30일 캐시 후 갱신) + Attribution 의무. 현재 미채택(ADR-0029) |
| T4 | **Apple/iTunes Search API** | **하** | 무인증 공개 엔드포인트. 약관상 **artwork URL 직접 링크 요구**(재호스팅 금지) → ADR-0029 가 준수 설계 |
| T5 | **MusicBrainz / Cover Art Archive** | **하** | CC0/CC 라이선스, rate limit 1 req/s + User-Agent 의무(`musicbrainz-integration.md`). 약관 가장 느슨 |
| T6 | **멜론/지니 등 국내 음원 플랫폼** | **상** | 공식 공개 API 부재 + 약관상 크롤링 금지 일반. **수집 경로로 비채택 권장** |

**완화 방안**
- **T1/T2/T6(상)**: 크롤링·약관 위반 경로는 **운영에서 채택하지 않는다**(현 결정 유지). 대체 =
  수기 큐레이션 시드 + CC0 출처(MusicBrainz) + 무인증 합법 엔드포인트(iTunes Search). 신규
  크롤링 도입 제안은 본 레지스터 + 후속 ADR 통과 전 금지.
- **T3(중)**: 채택 시 OAuth 토큰 관리 + 캐싱 제약(30일 갱신) + Attribution UI 준수 조건 충족
  필수. ADR-0029 가 비용 대비 과중으로 미채택 — 외부 식별자(ISRC/Spotify ID) 보관 후 재평가
  가치(`06-domain-model.md §7` 오픈 이슈 후보).
- **T4/T5(하)**: rate limit·User-Agent·재호스팅 금지 룰을 코드에 강제(`musicbrainz-integration.md`
  의 1 req/s, ADR-0029 의 이미지 미저장). 약관 변경 모니터링.

**오픈 이슈(이 축)**: 크롤링 전면 금지 정책을 형식 ADR 로 박제할지(→ §8 Q3),
robots.txt/약관 자동 점검 절차 부재.

### 5-3) 축 (3) — 사용자 음역대·기호 등 개인정보 처리·보관

mobruji 가 처리하는 개인 데이터:
- **음역대**(`VoiceRange`/`VoiceRangeSnapshot`) — 마이크 실측 시 음성 파생 데이터.
- **선호/기호**(`UserProfile.preferredGenres`/`preferredMoods`/`defaultGender`, like/bookmark).
- **익명 sessionId** — v0.2~v0.3 의 식별자(자칭, 위조 가능).
- **계정 정보**(v0.4, `User.email`/`passwordHash`/OAuth `providerUserId`).

| ID | 리스크 항목 | 등급 | 현 상태(완화 근거) |
|---|---|---|---|
| P1 | **음성 데이터(마이크 실측) 처리** — 음성은 민감 가능 정보. 원음 보관 시 리스크 | **하** | `voice-range-auto-measurement.md §5(비기능)`: 마이크 audio 스트림은 **브라우저 내에서만 처리·서버 미업로드**, 서버에는 산출 `lowMidi/highMidi` 정수만 전송 — 원음 비보존 원칙 **명문화됨** |
| P2 | **음역/기호 데이터 로그·노출** — 사용자 입력 원문 노출 시 프라이버시 침해 | **하** | `04-security-policy.md §2/§3`: 원문 로그/스크린샷 금지 + 마스킹·집계만. sessionId prefix 8자 마스킹(ADR-0011) |
| P3 | **무기한 보관 / 잊혀질 권리 부재** — 익명이라 본인 인증·삭제 통로 없음 | **하** | ADR-0013: 180일 inactive TTL + cascade-delete + 사용자 트리거 회전(`POST /sessions/rotate`). PIPA "장기 미접속 분리 보관"(365일)보다 보수적 |
| P4 | **sessionId 위조·추적** — 자칭 식별자라 노출 시 영구 추적 가능 | **중** | ADR-0011 1차 게이트(`X-Session-Id` 상수시간 비교) + ADR-0013 TTL. 본질 해결은 v0.4 정식 인증 |
| P5 | **계정 PII(이메일/비밀번호/OAuth)** — v0.4 | **중** | ADR-0011/`user-authentication-and-profile.md`: `passwordHash`/email/token 로그·응답 비노출. 정식 인증(Spring Security) 도입 시 ADR 갱신 |
| P6 | **개인정보 처리방침·수집 동의 부재** — 출시 시 법정 고지·동의 필요 | **상** | 현 단계 미작성. PIPA 상 수집·이용 목적 고지 + 동의가 출시 요건 — **출시 전 산출물 필요** |
| P7 | **개인정보 국외 이전** — 외부 CDN/API 로 사용자 데이터 전달 시 | **하** | 현 외부 호출은 곡 메타/커버용(사용자 PII 미전송). PII 를 외부로 보내는 경로 신설 시 재검토 |

**완화 방안**
- **P6(상)**: 출시 전 **개인정보 처리방침 + 수집·이용 동의 UX** 산출물 필요(별도, 법무 검토).
  본 spec 은 항목만 식별 — 실제 문구·동의 흐름은 출시 단계 별도 작업(→ §8 Q2).
- **P1(하)**: 마이크 실측은 **브라우저 내 처리·서버 미업로드 + MIDI 정수만 전송** 원칙이 이미
  명문화됨(`voice-range-auto-measurement.md §5`). 서버 사이드 audio 분석 경로(곡 분석 파이프라인,

  본 항목 재평가.
- **P4/P5(중)**: v0.4 정식 인증(Spring Security/JWT) 도입 시 ADR-0011/0013 superseded 트랙으로

- **P2/P3/P7(하)**: `04-security-policy.md` + ADR-0013 룰 유지·강제. 외부 PII 전송 경로 신설 시
