# 페르소나 확장 — 사회·감정 축 4종

## 1) 개요 (What / Why)

현 제품 북극성 페르소나 3종(`docs/roadmap/overnight-2026-06-02.md` §사용자 페르소나)은 **P-A 연습형 / P-B 부른곡 기반 / P-C 즉석 분위기·나이대** 로, 셋 다 *"한 사용자가 자기 자신을 위해 부를 곡을 찾는다"* 는 **개인·실용** 축에 몰려 있다. 노래방의 실제 사용 맥락에는 이 축으로 설명되지 않는 두 동기가 더 있다.

- **사회적 축** — 여러 명이 함께 있는 자리에서의 선곡(회식·MT 사회자, 둘이 부르는 듀엣).
- **감정 축** — "창피당하지 않고 싶다"(안전곡)와 "박수받고 싶다"(과시) 라는 정반대의 무대 감정.

본 spec 은 이 빈 축을 메우는 4 페르소나(P-D~P-G, 사용자 채택 2026-06-03 #1591)를 정의하고, 각 페르소나의 ① 입력 신호 ② 추천 로직 차별점 ③ 가용 데이터 vs 신규 필요 데이터 ④ 구현 단계를 명세한다. 기존 추천 도메인(음역대·성별·분위기·나이대·난이도·트렌딩/인기도)과 유비쿼터스 랭귀지 정합을 유지하며, **신규 추천 알고리즘을 새로 만드는 것이 아니라 기존 신호(`ScoreBreakdown` 7종)·read-model(`TrendingSong`/`SongAnalysisProfile`)을 페르소나별 가중 프리셋으로 재조합**하는 것을 원칙으로 한다.

- 대상 액터: 익명/회원 추천 요청자 — 추천 의도가 위 4 군 중 하나에 해당.
- 도메인 용어 등재: `06-domain-model.md §4-1` 에 `RecommendationPersona`(P-A~P-G) 등재 완료(본 PR 동반).

## 2) 페르소나 정의 (P-D~P-G)

> 양식은 `user-persona-and-pain-points.md §2` + 로드맵 P-A~C 정의와 정합. P-A~C 정의 SoT 는 `docs/roadmap/overnight-2026-06-02.md`. 본 절은 P-D~P-G 의 SoT.

### P-D 모임 사회자형 — "이 자리 다 같이 즐기게 하고 싶다"

| 항목 | 내용 |
|---|---|
| 축 | 사회적 |
| 핵심 니즈 | 회식·MT·동아리에서 **여러 명을 위해** 선곡을 대행. ① 다 같이 아는 곡 ② 분위기 흐름(워밍업→고조→마무리) 설계 ③ 특정인만 튀거나 소외되지 않게 |
| 입력 신호 | (선택) 인원 구성·연령대 분포 / 자리 단계(도입·절정·마무리) / 분위기 / (선택) 좌중 평균·공통 음역 힌트 |
| 기존 페르소나와 차이 | P-C(즉석 분위기·나이대)는 *나 한 명* 의 즉석 선곡. P-D 는 *집단* 의 곡 + **시퀀스**(한 곡이 아니라 흐름) |
| 현 만족도 | 부재 — 단일 추천만 있고 "다음 곡으로 분위기 끌어올리기" 시퀀스 개념 없음 |

### P-E 안전곡형 — "안 망하고 무사히 넘기고 싶다"

| 항목 | 내용 |
|---|---|
| 축 | 감정(불안 회피) |
| 핵심 니즈 | 음치·자신감 낮은 사용자. '안 망하는' 곡 = **좁은 음역 + 느린 템포 + 누구나 아는 곡**. 실력 향상이 목적이 아니라 **무사 통과** |
| 입력 신호 | 사용자 음역대(필수, 추천 구조상) / (암묵) "쉬운 곡" 의도 플래그 |
| 기존 페르소나와 차이 | **P-A(연습형)와 의도 정반대** — P-A 는 음역 천장·난이도를 *올려* 성장을 유도, P-E 는 음역 여유·난이도를 *낮춰* 실패 확률을 최소화 |
| 현 만족도 | 부재 — 난이도 신호는 있으나(`difficulty` EASY/NORMAL/HARD) "쉬운 쪽으로 강하게 편향" 하는 의도 모드가 없음 |

### P-F 과시·킬링파트형 — "고음 질러서 박수받고 싶다"

| 항목 | 내용 |
|---|---|
| 축 | 감정(과시) |
| 핵심 니즈 | 고음 도전, 임팩트. **사용자 음역 천장 근처**의 "킬링파트(후렴 고음·클라이맥스)" 가 있는 곡 |
| 입력 신호 | 사용자 음역대(특히 최고음) / (암묵) "도전·임팩트" 의도 플래그 |
| 기존 페르소나와 차이 | P-A(연습형)는 *반복 연습으로 뚫을* 곡 + 난이도·조옮김 보조. P-F 는 *지금 한 방* — 음역 천장 매칭 + **킬링파트 구간 메타** 가 핵심 차별 데이터 |
| 현 만족도 | 부재 — 음역 매칭은 있으나 "곡 안 어디가 임팩트 구간인지" 메타가 없음 |

### P-G 듀엣·함께 부르기형 — "둘이/같이 부를 곡"

| 항목 | 내용 |
|---|---|
| 축 | 사회적 |
| 핵심 니즈 | 남녀 듀엣·합창곡. 두 사람(또는 다수)이 파트를 나눠 부르기 좋은 곡 |
| 입력 신호 | 2인 이상 음역대(또는 성별 조합) / 듀엣 의도 |
| 기존 페르소나와 차이 | 기존 전 페르소나는 **단일 음역 입력 → 단일 사용자 적합**. P-G 는 **다중 음역/성별 입력** + 곡이 듀엣 구조인지(파트 분리) 라는 신규 곡 속성 필요 |
| 현 만족도 | 부재 — 다중 음역 입력 UX·듀엣곡 분류 둘 다 없음 |

## 3) 사용자 시나리오

1. **(P-D)** 회식 사회를 맡은 사용자가 "다 같이 즐길 곡" 모드 진입 → 인원 연령대·자리 단계(도입) 선택 → "도입용 누구나 아는 곡" 추천 → 한 곡 부른 뒤 "다음(고조)" → 점점 신나는 트렌딩 곡으로 시퀀스가 이어진다.
2. **(P-E)** 노래방에서 늘 긴장하는 사용자가 "안 망할 곡" 모드 진입 → 음역대만 입력 → 좁은 음역·느린 템포·대중적 곡만 강하게 편향된 안전 추천을 받는다.
3. **(P-F)** "한 곡 질러서 분위기 띄우고 싶은" 사용자가 "킬링파트 도전" 모드 진입 → 음역대 입력 → 자기 최고음 근처에 임팩트 구간이 있는 곡 + "이 곡 후렴 OO 부분이 킬링파트" 안내를 받는다.
4. **(P-G)** 연인이 "둘이 부를 곡" 모드 진입 → 두 사람 음역(또는 성별) 입력 → 두 음역 모두에 맞는 듀엣곡 + 파트 분담 표시를 받는다.

## 4) 요구사항

### 기능 요구사항
- [ ] (P-D) 집단 선곡 + **분위기 흐름 시퀀스**(워밍업→고조→마무리) 추천 — 단일 곡이 아니라 단계별 곡 묶음. 단계별로 트렌딩/인기도 + 분위기 신호 가중을 다르게 적용.
- [ ] (P-D) 특정인 비-과편향 가드 — 좌중 공통/평균 음역 힌트가 있으면 한쪽 극단(매우 높은/낮은 음역)으로 쏠리지 않게 중앙 편향.
- [ ] (P-E) 안전곡 모드 — `difficulty=EASY` + 좁은 `rangeFit` 여유 + 낮은 템포 + 높은 `popularity` 강편향. 결과 카드에 "안심 포인트"(쉬운 이유) 한 줄.
- [ ] (P-F) 킬링파트 모드 — 사용자 최고음 근접 + 임팩트(킬링파트) 메타 보유 곡 우선. 결과 카드에 킬링파트 구간 안내.
- [ ] (P-G) 듀엣 모드 — 다중 음역/성별 입력 + 듀엣곡 분류 필터 + 파트 분담 표시.
- [ ] 각 모드는 추천 응답에 페르소나 식별자(`RecommendationPersona`)와 페르소나별 사유 텍스트를 노출(설명 가능성, P2 정합).

### 비기능 요구사항
- 추천 **결정성 보존** — 같은 입력 → 같은 결과(기존 추천 알고리즘 불변식). 페르소나 가중 프리셋은 기존 `ScoreBreakdown` 신호의 *가중치 재조합* 으로만 표현하고, 신규 비결정 신호를 도입하지 않는다.
- 하위호환 — 페르소나 미지정(기존 호출 경로)은 현행 default 가중치로 동작. 신규 데이터(킬링파트·듀엣) 미보유 곡은 기여 0(중립) graceful 처리.
- 관측성 — 페르소나별 추천 호출 분포 메트릭(어느 모드가 쓰이는지) 노출.
- 데이터 정합 — 신규 곡 속성(킬링파트·듀엣)은 `SongAnalysisProfile`(`06-domain-model.md §4-1`·song-analysis-data-and-consumers.md) 계약 표면에 합류시키며 `metadataConfidence` 와 일관.

## 5) 설계

### 5-1) 페르소나 ↔ 추천 신호 매핑 (핵심)

기존 `ScoreBreakdown` raw 신호 7종(`keyMatch`/`rangeFit`/`genreMatch`/`moodMatch`/`popularity`/`tempoMatch`/`generationFit`)과 read-model(`TrendingSong.popularityScore`/`SongAnalysisProfile`)을 **페르소나별 가중 프리셋 + 필터** 로 재조합한다.

| 페르소나 | 1순위 신호 | 보조 신호 | 신규 필요 | 차별 로직 한 줄 |
|---|---|---|---|---|
| **P-D 모임 사회자** | `popularity`(다 같이 아는) + 단계별 `moodMatch`/`tempoMatch` | `generationFit`(연령대 분포) | **(無)** 시퀀스 추천 = 신규 추천 *형상*(단일→단계별 묶음). 데이터는 기존 | 단일 곡이 아니라 워밍업/고조/마무리 3단계 묶음을 단계별 다른 가중으로 산출 |
| **P-E 안전곡** | `difficulty=EASY` 필터 + `rangeFit`(여유 폭) | `tempoMatch`(느린 쪽) + `popularity`(대중적) | **(無)** 기존 `difficulty`(#1494 shipped) + `popularity`(#1488) 재사용 | "쉬운 쪽으로 강편향" — 난이도·템포·대중성 가중을 극단으로 올리고 도전 신호 억제 (P-A 가중의 거울) |
| **P-F 과시·킬링파트** | 사용자 최고음 근접도(파생) + 킬링파트 보유 | `keyMatch`/`moodMatch`(POWERFUL) | **킬링파트 메타**(미확보) — 곡 안 임팩트 구간 시각·강도 | 음역 천장 근접 + 임팩트 구간 보유 곡 우선. 메타 부재 시 음역 천장 근접만으로 1차 |
| **P-G 듀엣** | 듀엣곡 분류 필터 + 2인 `rangeFit` 동시 충족 | 성별 조합 적합 | **듀엣곡 태그/데이터셋 + 다중 음역 입력**(둘 다 미확보) | 단일 사용자 적합 → 두 음역 교집합 적합 + 파트 분리 곡만 |

### 5-2) 가용 데이터 vs 신규 필요 데이터 (구현 비용 평가)

evidence: `06-domain-model.md §4-1`/§5-2 + 각 기능 spec status 확인(2026-06-03).

| 데이터/신호 | 상태 | 출처 |
|---|---|---|
| 난이도 `difficulty`(EASY/NORMAL/HARD) | **확보**(shipped) — `Song` 컬럼 자동 분류 | `06-domain-model.md §5-2` PR #96 / #1494 |
| 분위기 `moodMatch`(연속 유사도) | **확보**(shipped) — 좌표 거리 기반 | `06-domain-model.md §4-1` / #1485 |
| 트렌딩/인기도 `TrendingSong`·`popularityScore` | **설계 완료**(implementing) — `Recommendation` 집계 view | trending-recommendation.md / #1488 |
| 템포 `tempoMatch` / `generationFit`(나이대) | **확보** — `ScoreBreakdown` 신호 | `06-domain-model.md §4-1` |
| `SongAnalysisProfile` 계약 표면 | **draft** — `lowMidi/highMidi/key/difficulty/mood/energy/confidence` | song-analysis-data-and-consumers.md / #1490 |
| **킬링파트(임팩트 구간) 메타** | **미확보** — `SongAnalysisProfile` 에 필드 없음. #1490 파이프라인 확장 필요 | (신규) |
| **듀엣곡 분류 + 파트 데이터** | **미확보** — 도메인 용어·곡 속성 전무 | (신규 데이터셋 확보 필요) |
| **다중 음역/성별 입력 UX·요청 모델** | **미확보** — `RecommendationRequest` 는 단일 음역 | (신규) |

→ **P-D / P-E 는 전부 확보된 데이터로 1차 구현 가능**. P-D 는 추천 *형상*(시퀀스)만 신규, 데이터는 기존. **P-F / P-G 는 신규 데이터 확보가 선행** — P-F 는 킬링파트 메타(#1490 확장), P-G 는 듀엣 데이터셋 + 다중 입력.

### 5-3) 도메인 모델

- `06-domain-model.md §4-1` 에 `RecommendationPersona`(P-A~P-G) 등재 완료(본 PR). 영속 엔티티 아님 — 추천 의도·가중 프리셋 분류 라벨.
- (2차) P-F 킬링파트 메타: `SongAnalysisProfile` 계약 표면에 신규 파생 속성 추가 — 정의는 별도 ADR + song-analysis-data-and-consumers.md 갱신 PR 에서. 본 spec 은 *수요* 만 박제.
- (2차) P-G 듀엣: 신규 곡 속성(듀엣 여부·파트 음역) + 다중 음역 요청 모델 — 별도 ADR(다중 음역 요청 계약) 필요(§8 Q3).

### 5-4) API 엔드포인트 (방향만 — 확정은 자식/구현 spec)

기존 `POST /api/v1/recommendations`(recommendation-algorithm-v1.md §5-2) 에 **페르소나 의도 선택 필드**(nullable, 하위호환)를 더하는 방향을 1차 가설로 한다. P-D 시퀀스·P-G 다중 입력은 응답/요청 형상이 단일 추천과 달라 별도 엔드포인트가 필요할 수 있다 — §8 Q1/Q3.

| Method | Path | 설명 | 비고 |
|---|---|---|---|
| POST | /api/v1/recommendations | (기존 확장) `persona` nullable 필드 → 가중 프리셋 적용 | P-E/P-F(단일 곡) 1차 후보 |
| POST | /api/v1/recommendations/sequence | (신규 후보) P-D 단계별 곡 묶음 | §8 Q1 |
| POST | /api/v1/recommendations/duet | (신규 후보, 2차) P-G 다중 음역 입력 | §8 Q3 |
