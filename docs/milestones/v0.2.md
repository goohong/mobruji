# v0.2 마일스톤 Roadmap

> v0.1.1 시점에서 정리한 v0.2 후보 백로그. 본 문서는 **가시화 목적**이며 사이클 launch는 별도로 진행한다.
> 우선순위는 `1(필수) / 2(권장) / 3(보류 가능)` 3단계.

## 0) v0.1.1 → v0.2 컨텍스트

- **메타 전략 pivot 확정** (2026-05-21): 외부 catalog 방대 import 폐기 → 큐레이션 + 자체 곡 분석 파이프라인 중심. (`docs/features/song-self-analysis-pipeline.md`, ADR 0006)
- be/fe/rev/plan 4세션 오케스트레이션 안정화. `docs/ai-harness/11-multi-session-runbook.md` 기준 운영.
- 운영 가능한 추천 e2e가 v0.1에서 닫혔다는 전제 (시드 30곡 + 음역대 입력 + 추천 응답).

## 1) v0.2 후보 백로그

### 1-1) [P1] 자체 곡 분석 파이프라인 PoC
- 출처: `docs/features/song-self-analysis-pipeline.md` (draft), ADR `0006-audio-source-youtube.md`.
- 작업: yt-dlp → Spleeter → Librosa pitch/key/tempo → `Song` update. 임시 캐시 + 분석 후 즉시 삭제.
- 의존: 시드 큐레이션(아래 1-2)이 분석 대상 리스트로 동작.
- 예상 사이클: be 사이클 2~3개 (파이프라인 import + batch runner + `metadataSource`/`metadataConfidence` 표기), plan 1개 (ADR `0007 자체 분석 도구 채택`).
- 의존 PR/이슈: #71, #67, #98, #99.

### 1-2) [P1] 음역대 큐레이션 100곡 시드 확장
- 출처: 이슈 #71. v0.1 시드 30곡 → 100곡.
- 작업: TJ/금영 인기 + Melon 차트 교차, 장르 분포(발라드 30/댄스 20/락 15/트로트 15/팝 10/힙합 10) 권장 default, `lowMidi/highMidi` 검증.
- 의존 PR: 없음 (단독 데이터 PR). 자체 분석 PoC 실행 전 선행되면 가장 효율.
- 예상 사이클: be 1개.

### 1-3) [P1] Song.difficulty enum + 노트명 응답 (#96 머지 후 자동 포함)
- 출처: 이슈 #77 / #95, PR #96 (draft, be 사이클 7 진행 중).
- 작업: 가창 난이도 분류(`EASY/NORMAL/HARD`) + `lowestNoteName/highestNoteName` 응답 노출.
- 의존 PR: PR #96 (이미 진행). 머지되면 v0.2 자동 산입.
- 후속 ADR 후보: `0007 가창 난이도 분류 기준` (be 사이클 7 머지 직후 plan 사이클로 채택 PoC 문서화).

### 1-4) [P1] ArchUnit 자동 검증 + application→api.dto 위반 fix
- 출처: 이슈 #94.
- 작업: ADR `0005-package-structure-migration` 후속. `application` 레이어가 `api.dto`를 참조하는 위반 fix + ArchUnit 룰 도입 (CI 게이트).
- 의존 PR: 없음 (백엔드 단독).
- 예상 사이클: be 1개. ADR `0008 ArchUnit 자동 검증 채택` plan 1개로 묶을 가치.

### 1-5) [P2] 곡 상세 페이지 + 추천 UX 다듬기
- 출처: 이슈 #100, PR #101 (draft, fe 사이클 9 진행 중).
- 작업: `/songs/[id]` 상세 페이지, 추천 결과 카드 UX 다듬기 (loading/error/empty state).
- 의존 PR: PR #101 (이미 진행). 1-3 응답 필드(노트명/difficulty) 머지 후 상세 페이지에 노출 확장 가능.
- 후속 후보: 추천 결과 상세 → 곡 상세 navigation, 음역대 시각화(피아노 건반/오선보).

### 1-6) [P2] MusicBrainz 메타 보강 (축소판)
- 출처: 이슈 #68.
- 작업: 메타(제목/아티스트/release/ISRC)만 보강. **audio features 미사용**. Spotify(#69)는 보류.
- 의존 PR: 없음. 1-1 자체 분석 결과와 충돌하지 않도록 `metadataSource` 표기 일관화 필요.
- 예상 사이클: be 1개. ADR 추가 불필요(메타 전략 pivot이 이미 ADR 0006으로 커버).

### 1-7) [P2] 추천 결과 영속화 + 사용자 피드백 (좋아요/북마크)
- 출처: 신규 (이슈 미등록). v0.1에서는 추천 응답이 in-memory.
- 작업: 추천 결과 row 영속화 (`RecommendationHistory`), 사용자 액션(`like/dismiss/bookmark`) 저장 + 추천 알고리즘에 feedback 반영(추후 단계).
- 새 spec 필요: `docs/features/recommendation-history-and-feedback.md` (신규). plan 1개.
- 예상 사이클: spec 1 + be 2 + fe 1 (액션 UI).
- 후속 ADR 후보: 없음 (스키마 추가는 spec 안에서).

### 1-8) [P2] recommendation p95 응답시간 회귀 가드
- 출처: 이슈 #62.
- 작업: spec `recommendation-algorithm-v1.md §3 비기능` 검증 자동화. p95 ms 회귀 시 CI 실패.
- 의존 PR: 없음.
- 예상 사이클: be 1개 또는 rev QA 사이클 1개로 흡수 가능.

### 1-9) [P3] 운영 진입 시 schema migration 도구 선택 (Flyway/Liquibase)
- 출처: PR #74 본문에서 미해결로 명시. 현재는 `spring.jpa.hibernate.ddl-auto`.
- 작업: ADR 신설 → 도구 선택 + 첫 마이그레이션 베이스라인.
- 의존: v0.2 운영 배포 결정 시점에 트리거. v0.1.1 직후 시급도는 낮음(개발 환경 한정 운영 중).
- 예상 사이클: plan 1 (ADR) + be 1 (도입 PR + baseline). 보호 영역(`**/db/migration/**`, `application*.yml`) 라벨 필수.

### 1-10) [P3] 후속 정비 백로그 (#43, #44, #56, #59, #61)
- 작은 refactor/컨벤션 보강 — be/fe 사이클 idle 룰(`11-multi-session-runbook.md §0-5`)로 자연스럽게 소화.
- 별도 마일스톤 작업으로 묶지 않고 idle 사이클에서 처리.

## 3) 새 ADR/spec 후보 (v0.2 동안 추가 예정)

### 3-1) 새 ADR 후보
- **`0007 가창 난이도 분류 기준`** — Song.difficulty 분류 규칙(범위/노트 분포/난이도 매핑). be 사이클 7 머지 후 plan 사이클로 채택.
- **`0008 ArchUnit 자동 검증 채택`** — 패키지 의존 룰(ADR 0005 후속). 이슈 #94와 묶음.
- **`0009 운영 schema migration 도구 채택`** — Flyway vs Liquibase. v0.2 운영 진입 결정 시점에 작성.
- **`0010 자체 곡 분석 도구 스택 채택`** — Spleeter + Librosa 선정 사유, 대안 비교. song-self-analysis-pipeline spec과 한 쌍.

### 3-2) 새 Feature Spec 후보
- **`recommendation-history-and-feedback.md`** — 1-7과 한 쌍. 추천 결과 영속화 + 좋아요/북마크 도메인.
- **`song-curation-seed-100.md`** (선택) — 1-2 큐레이션 기준을 spec으로 별도 보존. 단순 데이터 작업이면 spec 생략하고 이슈 본문만으로도 충분.
- **`voice-range-auto-measurement.md`** (draft, PR #144 / closes #143) — Vanido 영감(F-1 P1 후보). v0.2 후반 또는 v0.3 초반 도입 후보. 백엔드 변경 없이 fe 단독 사이클로 진행 가능.
